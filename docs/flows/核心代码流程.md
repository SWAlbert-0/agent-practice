# 核心代码流程

核对日期：2026-10-16。这些图描述当前源码的静态执行路径，不是运行日志。前端通过 `web/flows.json` 提取本文的 Mermaid 代码块；修改图后运行 `python web/generate_sources.py` 更新索引。

阅读背景见 [Agent 设计与执行流程](../Agent设计与执行流程.md) 与 [LLM 源码分析](../HelloAgentsLLM源码与执行流程分析.md)。本文按源码分支展开，项目整体结构以入口文档为准。

前七个 Mermaid 图块按 0–6 编号被前端引用，保持顺序；新增图应同时维护 `web/flows.json`。计算器编排时序图独立维护在 [计算器工具调用流程](../计算器工具调用流程.md)。

## 1. 模型配置解析

`core/llm.py:create_llm` 显式解析同一服务的模型、地址和密钥，再创建框架客户端。未提供的 JSON 键会按 Python 原有行为报错；当前函数没有额外的配置结构校验。

```mermaid
flowchart TD
    A[create_llm] --> B[load_dotenv 加载项目环境变量]
    B --> C[读取并解析 models.json 或指定配置文件]
    C --> D[参数 provider 或 defaultProvider]
    D --> E[取 providers 中对应的服务配置]
    E --> F[参数 model 或 defaultModel]
    F --> G[读取同一配置的 baseUrl]
    G --> H{配置 apiKeyEnv?}
    H -->|是| I[从环境变量取 API Key]
    H -->|否| J[读取配置中的 apiKey]
    I --> K{密钥非空?}
    J --> K
    K -->|否| L[抛出 ValueError]
    K -->|是| M[显式传入 provider / model / base_url / api_key]
    M --> N[返回 HelloAgentsLLM 实例]
```

## 2. main 的流式请求

`main.py` 直接使用模型客户端，没有经过 Agent 或工具注册表。`think()` 是生成器，实际请求发生在迭代时；它自身也打印输出，调用方再次打印可能重复。

```mermaid
sequenceDiagram
    autonumber
    participant Main as main.py
    participant Factory as create_llm
    participant LLM as HelloAgentsLLM
    participant API as 配置的模型服务
    Main->>Factory: create_llm()
    Factory-->>Main: 模型客户端
    Main->>LLM: think(messages)
    LLM-->>Main: 返回生成器
    Main->>LLM: for chunk 开始迭代
    LLM->>API: 发送一次流式请求
    loop 接收响应片段
        API-->>LLM: 响应片段
        LLM-->>Main: yield 文本片段
    end
    Note over LLM,API: 请求目标由 base_url 决定，模型由 model 决定
```

## 3. SimpleAgent 普通对话

这是自定义 `agents/simple_agent.py` 的无工具分支；历史方法和 Message 来自安装的框架，与项目 `core/agent.py` 不同。

```mermaid
sequenceDiagram
    autonumber
    participant Caller as 调用方
    participant Agent as 自定义 SimpleAgent
    participant History as 框架 Agent 历史
    participant LLM as HelloAgentsLLM
    participant API as 模型服务
    Caller->>Agent: run(input_text)
    Agent->>History: get_history()
    History-->>Agent: 历史列表的浅拷贝
    Agent->>Agent: system + history + user
    Note over Agent,LLM: 未启用工具的分支
    Agent->>LLM: invoke(messages)
    LLM->>API: 非流式模型请求
    API-->>LLM: 完整响应
    LLM-->>Agent: response 字符串
    Agent->>History: add_message(user)
    Agent->>History: add_message(assistant)
    Agent-->>Caller: return response
```

## 4. SimpleAgent 工具循环

当前实现解析文本协议 `[TOOL_CALL:工具名:参数]`，不是原生 function calling。达到迭代上限后补充的一次回答不会再次解析工具标记。

```mermaid
flowchart TD
    A[run 组织上下文] --> B{启用工具且有注册表?}
    B -->|否| C[invoke 普通回答]
    B -->|是| D[进入 _run_with_tool_calling]
    D --> E{迭代次数小于上限?}
    E -->|是| F[LLM.invoke 获取响应]
    F --> G[_parse_tool_calls 解析文本标记]
    G --> H{有工具标记?}
    H -->|否| I[取当前响应作为最终回答]
    H -->|是| J[逐个 _execute_tool_call]
    J --> K{名称是 calculator?}
    K -->|是| L[框架 registry.execute_tool]
    K -->|否| M[解析参数 / get_tool / tool.run]
    L --> N[清理标记并追加 assistant 和 user 工具结果]
    M --> N
    N --> O[迭代次数加一]
    O --> E
    E -->|否| P[额外 invoke 一次 / 不再解析工具]
    P --> Q[保存原始用户消息和最终回答]
    I --> Q
    C --> Q
    Q --> R[返回最终回答]
```

## 5. SimpleAgent 流式对话

流式方法当前不执行工具循环。调用方若提前停止迭代，方法尾部保存历史的代码尚未执行。

```mermaid
sequenceDiagram
    autonumber
    participant Caller as 调用方
    participant Agent as SimpleAgent.stream_run
    participant History as 框架 Agent 历史
    participant LLM as HelloAgentsLLM
    participant API as 模型服务
    Caller->>Agent: stream_run(input_text)
    Agent-->>Caller: 返回生成器
    Caller->>Agent: 开始迭代
    Agent->>History: get_history()
    History-->>Agent: 历史列表
    Agent->>Agent: 组织 system / history / user
    Agent->>LLM: stream_invoke(messages)
    LLM->>API: 流式请求
    loop 每个响应片段
        API-->>LLM: chunk
        LLM-->>Agent: yield chunk
        Agent->>Agent: 累积 full_response
        Agent-->>Caller: yield chunk
    end
    Agent->>History: 完整迭代后保存 user 和 assistant
    Note over Caller,History: 提前停止消费生成器时，不保证保存历史
```

## 6. 计算器递归求值

`ast.parse` 只解析语法树。求值由项目 `_eval_node` 自行递归完成。运算表虽然包含正负号，但当前没有 `UnaryOp` 分支；未匹配的节点可能返回 None。图保留这个实际边界。

```mermaid
flowchart TD
    A[calculate expression] --> B{表达式为空?}
    B -->|是| C[返回空表达式错误文本]
    B -->|否| D[构建运算表和 sqrt / pi 白名单]
    D --> E[ast.parse mode=eval]
    E --> F[_eval_node node.body]
    F --> G{节点类型}
    G -->|Constant| H[返回 node.value]
    G -->|BinOp| I[递归左右子节点 / 查运算表 / 执行运算]
    G -->|Call| J[取函数名 / 白名单匹配 / 递归参数 / 调用]
    G -->|Name| K[白名单中读取常量]
    G -->|其他或名称未匹配| L[当前实现可能隐式返回 None]
    H --> M[str result]
    I --> M
    J --> M
    K --> M
    L --> M
    E -.指定类型异常.-> N[返回计算失败文本]
    F -.指定类型异常.-> N
    Note[未实现 UnaryOp 分支 / 不是所有异常都会捕获] --- L
```

## 7. 本地注册表

这里是项目 `tools/registry.py`，不是框架同名类。对象能注册，但 `execute_tool()` 当前只查找函数表。`to_openai_schema()` 所需的 get_parameters、name、description 不在本类中定义，暂不视为可工作的接入路径。

```mermaid
flowchart TD
    A[create_calculator_registry] --> B[创建项目 ToolRegistry]
    B --> C[register_function my_calculator → calculate]
    C --> D[保存到 _functions]
    E[register_tool 对象] --> F[保存到 _tools]
    G[execute_tool name / parameters] --> H{名称在 _functions?}
    H -->|是| I[取出 func]
    I --> J[func parameters]
    J --> K[返回函数结果]
    H -->|否| L[返回工具不存在]
    D -.供查询.-> H
    F -.当前执行方法不查询对象表.-> L
```

## 维护核对

- 流式文本必须消费生成器后再做解析或保存，不能直接把生成器当字符串。
- 图中 SimpleAgent 使用框架历史与注册表，本地计算器使用本地注册表，路径需分别核对。
- 这些图只覆盖列出的核心场景，ReflectionAgent、ReActAgent、PlanAndSolveAgent 的循环说明见 [Agent 设计与执行流程](../Agent设计与执行流程.md)。
