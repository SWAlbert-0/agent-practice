# 核心代码流程

核对日期：2026-10-17。这些图描述当前源码的静态执行路径，不是运行日志。前端通过 `web/flows.json` 提取本文的 Mermaid 代码块；修改图后运行 `python web/generate_sources.py` 更新索引。

阅读背景见 [Agent 设计与执行流程](../Agent设计与执行流程.md)、[LLM 源码与执行流程分析](../LLM源码与执行流程分析.md) 与 [本地 LLM 源码](../../core/llm.py)。本文按源码分支展开，项目整体结构以入口文档为准。

前七个 Mermaid 图块按 0–6 编号被前端引用，后续图块用于请求参数与其他 Agent；新增图应同时维护 `web/flows.json`。计算器编排时序图独立维护在 [计算器工具调用流程](../计算器工具调用流程.md)。

## 1. 模型配置解析

`core/llm.py:create_llm` 显式解析同一服务的模型、地址和密钥，再创建本地 LLM 客户端。未提供的 JSON 键会按 Python 原有行为报错；当前函数没有额外的配置结构校验。

```mermaid
flowchart TD
    A[create_llm] --> B[load_dotenv 加载项目环境变量]
    B --> C[读取并解析 models.json 或指定配置文件]
    C --> D[参数 provider 或 defaultProvider]
    D --> E[取 providers 中对应的服务配置]
    E --> F[参数 model 或 defaultModel]
    F --> G[读取同一配置的 baseUrl]
    G --> H{配置 apiKeyEnv?}
    H -->|是| I[从环境变量取 API Key]
    H -->|否| J[读取配置中的 apiKey]
    I --> K{密钥非空?}
    J --> K
    K -->|否| L[抛出 ValueError]
    K -->|是| M[显式传入 provider / model / base_url / api_key]
    M --> N[返回本地 LLM 实例]
```

## 2. main 的流式请求

`main.py` 直接使用模型客户端，没有经过 Agent 或工具注册表。`think()` 是生成器，实际请求发生在迭代时；它自身也打印输出，调用方再次打印可能重复。

```mermaid
sequenceDiagram
    autonumber
    participant Main as main.py
    participant Factory as create_llm
    participant LLM as 本地 LLM
    participant API as 配置的模型服务
    Main->>Factory: create_llm()
    Factory-->>Main: 模型客户端
    Main->>LLM: think(messages)
    LLM-->>Main: 返回生成器
    Main->>LLM: for chunk 开始迭代
    LLM->>API: 发送一次流式请求
    loop 接收响应片段
        API-->>LLM: 响应片段
        LLM-->>Main: yield 文本片段
    end
    Note over LLM,API: 请求目标由 base_url 决定，模型由 model 决定
```

## 3. SimpleAgent 普通对话

这是 `agents/simple_agent.py` 的无工具分支；继承本地 `core/agent.py` 的 Agent，使用本地 Message 和 Config。

```mermaid
sequenceDiagram
    autonumber
    participant Caller as 调用方
    participant Agent as 自定义 SimpleAgent
    participant History as 本地 Agent 历史
    participant LLM as 本地 LLM
    participant API as 模型服务
    Caller->>Agent: run(input_text)
    Agent->>History: get_history()
    History-->>Agent: 历史列表的浅拷贝
    Agent->>Agent: system + history + user
    Note over Agent,LLM: 未启用工具的分支
    Agent->>LLM: invoke(messages)
    LLM->>API: 非流式模型请求
    API-->>LLM: 完整响应
    LLM-->>Agent: response 字符串
    Agent->>History: add_message(user)
    Agent->>History: add_message(assistant)
    Agent-->>Caller: return response
```

## 4. SimpleAgent 工具循环

当前实现解析文本协议 `[TOOL_CALL:工具名:参数]`，不是原生 function calling。达到迭代上限后补充的一次回答不会再次解析工具标记。

```mermaid
flowchart TD
    A[run 组织上下文] --> B{启用工具且有注册表?}
    B -->|否| C[invoke 普通回答]
    B -->|是| D[进入 _run_with_tool_calling]
    D --> E{迭代次数小于上限?}
    E -->|是| F[LLM.invoke 获取响应]
    F --> G[_parse_tool_calls 解析文本标记]
    G --> H{有工具标记?}
    H -->|否| I[取当前响应作为最终回答]
    H -->|是| J[逐个 _execute_tool_call]
    J --> K{名称是 calculator?}
    K -->|是| L[本地 registry.execute_tool]
    K -->|否| M[解析参数 / get_tool / tool.run]
    L --> N[清理标记并追加 assistant 和 user 工具结果]
    M --> N
    N --> O[迭代次数加一]
    O --> E
    E -->|否| P[额外 invoke 一次 / 不再解析工具]
    P --> Q[保存原始用户消息和最终回答]
    I --> Q
    C --> Q
    Q --> R[返回最终回答]
```

## 5. SimpleAgent 流式对话

流式方法当前不执行工具循环。调用方若提前停止迭代，方法尾部保存历史的代码尚未执行。

```mermaid
sequenceDiagram
    autonumber
    participant Caller as 调用方
    participant Agent as SimpleAgent.stream_run
    participant History as 本地 Agent 历史
    participant LLM as 本地 LLM
    participant API as 模型服务
    Caller->>Agent: stream_run(input_text)
    Agent-->>Caller: 返回生成器
    Caller->>Agent: 开始迭代
    Agent->>History: get_history()
    History-->>Agent: 历史列表
    Agent->>Agent: 组织 system / history / user
    Agent->>LLM: stream_invoke(messages)
    LLM->>API: 流式请求
    loop 每个响应片段
        API-->>LLM: chunk
        LLM-->>Agent: yield chunk
        Agent->>Agent: 累积 full_response
        Agent-->>Caller: yield chunk
    end
    Agent->>History: 完整迭代后保存 user 和 assistant
    Note over Caller,History: 提前停止消费生成器时，不保证保存历史
```

## 6. 计算器递归求值

`ast.parse` 只解析语法树。求值由项目 `_eval_node` 自行递归完成。运算表虽然包含正负号，但当前没有 `UnaryOp` 分支；未匹配的节点可能返回 None。图保留这个实际边界。

```mermaid
flowchart TD
    A[calculate expression] --> B{表达式为空?}
    B -->|是| C[返回空表达式错误文本]
    B -->|否| D[构建运算表和 sqrt / pi 白名单]
    D --> E[ast.parse mode=eval]
    E --> F[_eval_node node.body]
    F --> G{节点类型}
    G -->|Constant| H[返回 node.value]
    G -->|BinOp| I[递归左右子节点 / 查运算表 / 执行运算]
    G -->|Call| J[取函数名 / 白名单匹配 / 递归参数 / 调用]
    G -->|Name| K[白名单中读取常量]
    G -->|其他或名称未匹配| L[当前实现可能隐式返回 None]
    H --> M[str result]
    I --> M
    J --> M
    K --> M
    L --> M
    E -.指定类型异常.-> N[返回计算失败文本]
    F -.指定类型异常.-> N
    Note[未实现 UnaryOp 分支 / 不是所有异常都会捕获] --- L
```

## 7. 本地注册表

这里是项目 `tools/registry.py`。`execute_tool()` 先查询对象表，再查询函数表，对象与函数同名时优先对象。`to_openai_schema()` 所需的 get_parameters、name、description 不在本类中定义，暂不视为可工作的接入路径。

新增高级搜索工厂也使用同一注册机制，将名称 `advanced_search` 映射到实例的 `search` 绑定方法；下图以计算器为例，函数调度路径相同。它们的工厂分别创建新注册表，不会自动合并。

```mermaid
flowchart TD
    A[create_calculator_registry] --> B[创建项目 ToolRegistry]
    B --> C[register_function calculate → calculate]
    C --> D[保存到 _functions]
    E[register_tool 对象] --> F[保存到 _tools]
    G[execute_tool name / parameters] --> P{名称在 _tools?}
    P -->|是| Q[调用对象 run / input 字典]
    Q --> K[返回工具结果]
    P -->|否| H{名称在 _functions?}
    H -->|是| I[取出 func]
    I --> J[func parameters]
    J --> K
    H -->|否| L[返回工具不存在]
    D -.供查询.-> H
    F -.供查询.-> P
```

## 8. LLM 统一请求

`invoke()` 和 `think()` 共用 `_request()`。调用选项覆盖默认值后，stream 再由入口强制指定。构造参数 timeout 传给 SDK；请求异常直接传播，不进行框架包装。

```mermaid
flowchart TD
    A[LLM.invoke] --> B{本次 stream 为真?}
    B -->|是| C[抛出 ValueError]
    B -->|否| D[调用 _request / stream=False]
    E[LLM.think 开始迭代] --> F[可选 temperature 写入 kwargs]
    F --> G[调用 _request / stream=True]
    D --> H[默认 model / messages / temperature]
    G --> H
    H --> I[可选默认 max_tokens]
    I --> J[options 覆盖默认参数]
    J --> K[最后强制当前入口的 stream]
    K --> L[SDK chat.completions.create]
    L --> M{当前入口}
    M -->|invoke| N[第一项 content 或空字符串]
    M -->|think| O[with 管理流 / 跳过空事件 / 打印并 yield]
```

## 9. ReAct 推理与行动

本地 ReActAgent 直接继承本地 Agent。构造时使用非空 `custom_prompt`，否则回退 `DEFAULT_REACT_PROMPT`；之后每次 `run()` 沿用选定模板。每轮提示词包括工具描述、问题与本轮 Action / Observation；`system_prompt` 和已存问答未单独加入模型消息。无 Action 也消耗步数，工具抛出的异常不会在本循环内统一捕获。

```mermaid
flowchart TD
    Init[ReActAgent.__init__] --> Template{custom_prompt 非空?}
    Template -->|是| Custom[使用 custom_prompt]
    Template -->|否| Default[DEFAULT_REACT_PROMPT]
    Custom --> A
    Default --> A
    A[ReActAgent.run] --> B[清空 current_history / 步数归零]
    B --> C{步数小于 max_steps?}
    C -->|否| D[保存问答 / 返回超限提示]
    C -->|是| E[步数加一 / 工具说明与轨迹格式化模板]
    E --> F[LLM.invoke]
    F --> G[_parse_output 提取 Thought / Action]
    G --> H{Action 以 Finish 开头?}
    H -->|是| I[_parse_action_input 提取答案]
    I --> J[本地 Message 保存问答 / 返回]
    H -->|否| K{存在 Action?}
    K -->|否| C
    K -->|是| L[_parse_action 拆分工具名与输入]
    L --> M[ToolRegistry.execute_tool]
    M --> N[追加 Action / Observation]
    N --> C
```

## 10. 先规划再求解

PlanAndSolveAgent 是组合 Planner 和 Executor 的独立类，不继承 Agent。执行步骤是模型解答，不是实际工具执行；最终返回最后一步回答，不额外汇总。

```mermaid
flowchart TD
    A[PlanAndSolveAgent.run] --> B[Planner.plan]
    B --> C[消费 LLM.think / 拼接完整计划文本]
    C --> D[提取 python 围栏 / literal_eval]
    D --> E{解析为非空列表?}
    E -->|否| F[停止 / 返回 None]
    E -->|是| G[Executor.execute]
    G --> H[逐步组织问题 / 计划 / 先前结果]
    H --> I[消费 LLM.think / 保存步骤结果]
    I --> J{还有步骤?}
    J -->|是| H
    J -->|否| K[返回最后一步回答]
```

## 11. 反思与改进

ReflectionAgent 每次运行重置 Memory。execution 是生成内容，不表示执行了生成代码；反思由同一个模型完成。

```mermaid
flowchart TD
    A[ReflectionAgent.run] --> B[重置 Memory]
    B --> C[_get_llm_response / 初始回答]
    C --> D[Memory.add_record execution]
    D --> E{反思轮数未用完?}
    E -->|否| K[返回 Memory.get_last_execution]
    E -->|是| F[读取最近 execution / 请求反思]
    F --> G[记录 reflection]
    G --> H{反馈去空白后等于无需改进?}
    H -->|是| K
    H -->|否| I[根据反馈请求改进]
    I --> J[记录 execution / 进入下一轮]
    J --> E
```

## 维护核对

- 流式文本必须消费生成器后再做解析或保存，不能直接把生成器当字符串。
- SimpleAgent 与 ReActAgent 使用同一套本地 Agent、Message、Config、LLM 与注册表。
- 这些图只覆盖列出的核心场景，ReflectionAgent、ReActAgent、PlanAndSolveAgent 的循环图已加入上文，职责说明见 [Agent 设计与执行流程](../Agent设计与执行流程.md)。
